## 규칙을 변경할 때의 버전 관리

1. 새 요청을 현재의 지침·검수기준·운영법·판단 가이드·스타일 중 관련된 **기존 파일에 통합**한다. 변경 규칙을 채팅에만 남기거나 별도 추가 파일로 운영하지 않는다. 기존 규칙과 충돌하는 문장도 함께 고쳐서 한 버전 안에서 지시가 모순되지 않게 한다.
2. 다섯 파일을 새 버전으로 만들고 파일명, 문서 안의 규칙 버전, 상호 링크, 프로젝트 설정의 지침 문구를 모두 맞춘다. 보고서에는 실제 사용한 규칙 버전을 남기며 예전 PDF의 버전이나 점수를 소급 변경하지 않는다.
3. 새 파일과 지침을 준비·검토한 후 Sources에 새 버전 다섯 파일을 올리고 프로젝트 설정 지침을 갱신한다. 업로드·저장 결과를 확인한 다음 **구버전 규칙·프롬프트·스타일 파일을 모두 삭제**한다. 마지막으로 Sources에 최신 다섯 파일만 있는지 확인한다. 오래된 채팅이 이전 맥락을 가진 경우 새 프로젝트 채팅에서 새 버전으로 검사를 시작한다.

## URL만 입력했을 때

새 채팅에 공개 URL 한 줄을 입력한다. 그러면 다음 **두 가지를 따로** 선택한다.

> 검사할 페이지 수를 알려 주세요(1~200개, 추천 10·30·50개). 검사 방식도 골라 주세요: ① 빠른 검사 ② 정밀 검사. 제외할 공개 경로가 있으면 함께 적어 주세요. 없으면 제외 경로 없이 진행합니다.

예: `30개, 정밀 검사, /members/ 제외` 또는 `10개, 빠른 검사, 제외 없음`. 페이지 수는 **목표 방문 수**다. 실제 방문이 더 적거나 일부만 읽혔으면 보고서에 실제 URL·수·이유가 나온다. 200개 지정은 오래 걸릴 수 있으며 한 번의 작업에서 전부 방문할 수 있다고 보장하지 않는다.

| 방식 | 실제로 시도할 검사 | 적합한 경우 |
|---|---|---|
| 빠른 검사 | 각 선택 페이지의 보이는 본문·탐색·핵심 링크, 공통 정책 페이지를 우선 확인 | 후보 결함을 빨리 추려야 할 때 |
| 정밀 검사 | 빠른 검사의 항목에 더해 도구가 허용하는 원본 HTML·응답·robots·ads.txt·데스크톱/모바일 화면·주요 자원 등을 확인 | 고객용 상세 보고서가 필요할 때 |

**빠른 검사를 30개 선택해도 30개를 실제로 열어야 `검사 30개`라고 쓴다.** 두 방식 모두 확인하지 못한 항목은 확인 불가이며, 도구에서 열리지 않은 페이지의 HTTP 오류·Google 크롤러 차단을 추측하지 않는다. 도구가 컴퓨터 사용을 지원하면 대표 페이지와 결함 의심 페이지를 화면으로 재확인한다. 고객의 사이트 언어와 페이지 유형에 맞춰 대표 URL을 고르며, 특정 언어나 URL 구조를 강요하지 않는다.

## 직접 접속 사전 점검

**검색 도구의 `open`/검색 캐시가 실패한 뒤 같은 호출만 반복하지 않는다.** 먼저 Work 코드·셸에서 `GET`으로 공개 테스트 URL과 대상 홈을 실제 요청한다. `HEAD`나 검색 스니펫으로 HTML 확인을 대신하지 않는다. 응답의 상태코드·최종 URL·리다이렉트 단계·소요 시간·콘텐츠 유형·HTML 바이트 수·시각을 기록한다. 요청과 리다이렉트가 공개 `http/https` 주소인지 매 단계 확인하고, 사설망·localhost·인증 정보가 있는 URL은 열지 않는다. 연결/전체 타임아웃, 최대 리다이렉트 수, 도메인별 요청 속도를 제한하고 일시적인 전송 오류만 최대 두 번 재시도한다. 실제 HTTP 4xx·5xx는 재시도로 감추지 않는다.

Work 셸의 외부 인터넷이 막혔다면 클라우드 브라우저에서 **주소창으로 대상 URL을 직접 방문**한다. 브라우저에서 읽은 제목·본문·화면은 직접 관찰이지만, 브라우저가 제공하지 않은 원시 HTTP 코드·리다이렉트 체인·HTML 바이트 수는 `미확인`이다. 클라우드 브라우저까지 열지 못한다면 `검사 환경의 외부 네트워크 제한`인지 `대상 사이트/브라우저 차단`인지 관찰된 오류만으로 구분하고, 증거가 부족하면 `원인 미확인`으로 둔다. 이 경우 관리자가 로컬 채점기에서 직접 검증 JSON을 내보내 **이번 채팅에 첨부**할 수 있다. ChatGPT 웹이 관리자 Mac의 로컬 서버에 직접 접속한 것처럼 쓰지 않는다.

직접 접속이 가능한 경우 `/robots.txt`, `/sitemap.xml`, `/ads.txt`를 각각 GET하고, 대상 페이지의 데스크톱·모바일 화면을 각각 렌더링한다. 스크린샷을 저장할 수 있으면 관찰 근거에 연결한다. 원본 HTML이 성공하고 브라우저 렌더링만 실패했다면 원본 판정은 보존하고 화면 의존 규칙만 미확인으로 둔다. 실행마다 새 ID·시각·URL별 결과를 저장한다. `다시 검사` 요청은 같은 범위를 새 실행으로 검사하며 이전 자료를 덮어쓰지 않는다.

## 작업 흐름

1. 위 사전 점검에서 실제 직접 접속 경로를 확보한 뒤 입력 URL과 공개 사이트맵·내부 링크에서 후보를 찾고 직접 GET/브라우저로 실제 연 URL만 `방문`으로 기록한다. 홈·운영자 정보·개인정보 안내·주요 콘텐츠와 여러 경로·콘텐츠 유형을 고르게 포함한다. 제외 경로는 열지 않는다. 직접 접속이 전부 실패하면 후보 탐색만 계속하지 말고 검사 환경 진단으로 전환한다.
2. 검사 시작과 각 페이지의 실제 관찰 시점을 따로 남긴다. 각 장부 행에는 요청·최종 URL·상태코드·리다이렉트 경로·응답 시간·HTML 수집 여부·데스크톱/모바일 렌더링·실패 분류·규칙 ID·**확인 가능한 연·월·일·시각·시간대**·도구·읽은 범위·짧은 증거·미확인 이유를 연결한다. 도구가 정확한 시각을 제공하지 않으면 날짜와 `정확한 시각 미확인`으로 기록한다. 검색 결과의 제목이나 사이트맵 주소만으로 본문을 읽었다고 쓰지 않는다. 긴 페이지가 일부만 출력되면 추가로 읽거나, 못 읽은 범위는 확인 불가로 둔다.
3. 중대한 결함과 날짜·가격·기간처럼 바뀌는 정보는 PDF 직전에 해당 페이지에서 다시 확인하고 **재확인 시점**을 기존 관찰 시점과 따로 남긴다. 다른 도구의 결과가 충돌하면 판단을 보류한다. 판정마다 실제 관찰과 공식 근거 링크가 일치하는지 점검한다. 화면 관찰 0건이면 콘텐츠 대비 광고·홍보 비중 및 모바일 화면 규칙은 검증 W=0으로 두며 양호·만점을 추측하지 않는다. 현재 버전의 Sources 원문을 못 읽으면 과거 PDF로 재구성하지 않고 중지한다.
4. 규칙별 측정·미측정 가중치를 검산한다. 직접 확인한 HTML·브라우저 문서 1개 이상·T>0·W>0이면 선택한 실제 방문 N페이지 집합의 **통합 잠정 성적 S=100E/W점/100점**과 동일 숫자의 **비공식 AdSense 승인 가능성 추정 지수 S%**를 첫 장에 가장 크게 표시한다. N은 목표 수가 아니라 실제 직접 방문한 고유 URL 수다. 확인분 E/W는 총점이 아니라 보조 검증 정보다. 미확인 U는 점수에 넣지 않고 검증률 W/T·이유·가능 구간 100E/T~100(E+U)/T에 쓴다. T=0·직접 확인 페이지 0개·W=0이면 평가 불가 이유와 재검사 방법을 적는다. Google 공식 필수 정책의 중대 위반을 실제 재방문과 현재 정책 원문으로 확인한 경우에만 S최종=min(S,39) 상한을 적용한다. 첫 장에는 5영역 명목 배점 40/20/15/15/10과 19개 세부 항목의 이름·배점을 표로 모두 제시하고, 실제 영역별 Tᵢ/Wᵢ/Eᵢ/Uᵢ·성적률·미확인 이유는 이어지는 읽기 쉬운 성적표에 적는다. Wᵢ=0은 미검증, Tᵢ=0은 해당 없음이다. X%는 실제 통계적 승인 확률이나 Google 심사 결과가 아님을 바로 옆에 명시한다.
5. [보고서 스타일](./ChatGPT-보고서-스타일-v11.css)을 적용한 한국어 HTML에서 PDF를 만든다. 첫 장은 `N페이지 통합 X/100점`·동일 X%·점수 기준표·작은 검증 상세다. 이후에는 심각도 **크리티컬 → 긴급 → 수정 필요**로 구분하고, 각 섹션에서 페이지 **전체 URL별** 수정 카드를 보여준다. 양호 항목과 좋은 점 요약은 관리자 장부에만 남기고 고객 PDF에서 제외한다. 각 카드에는 현재 상황·관찰 위치·시각, 실제 수집한 공개 HTML/DOM의 짧은 발췌 또는 `소스 확인 불가`, 지적·방문자 영향, 직접 관련된 공식 정책/권장사항/자체 기준 링크, 구체적인 수정 목표와 조건부 전/후 코드 예시, 적용하면 안 되는 상황·절충안, 수정 후 URL별 검증 방법을 서로 다른 행에 쓴다. 공개 HTML을 봤어도 저장소 소스와 같다고 단정하지 않고 파일명·프레임워크를 꾸미지 않는다. 동일 현상도 각 URL의 관찰·시각을 분리한다. 확정할 수 없는 항목은 심각도 카드가 아니라 `추가 확인 필요`에 둔다. 19개 규칙 계산표·기술 항목·검사 URL 목록은 뒤 부록에 두되 양호 평가문은 싣지 않는다. 첫 장·심각도 카드가 있는 장·마지막 장을 100% 배율로 열어 점수 기준, 전체 URL, HTML 발췌, 날짜와 시간대, 링크, 글자 크기, 표·카드 잘림, 검색엔진 안내를 확인한다. PDF가 없으면 완료라고 말하지 않는다.
6. 관리자가 방문 URL 수, 중대한 지적의 재확인 여부, 검증률, 점수 계산과 PDF를 검토한 뒤 고객에게 직접 전송한다. 프로그램이 이메일·메시지를 자동으로 보내지 않는다.

## 직접 접속 0건일 때의 진단 PDF

검색 도구 `Cache miss`만 있고 직접 HTML·브라우저 관찰이 0건이면 **성적표 형식을 억지로 채우지 않는다.** 첫 장의 총점·비공식 승인 가능성 추정 지수 자리는 모두 `평가 불가`로 쓰고, 바로 아래에 `직접 확인 페이지 0 / 시도 URL N`과 **산출 보류 이유**를 적는다. `0점`, `승인 가능성 0%`, 사이트 오류 확정 또는 검색 색인만으로 만든 긍정 판정은 금지한다. 진단 PDF도 아래 스타일 파일을 실제로 적용하고 검색 도구 자가 확인 표를 맨 아래에 둔다.

이어지는 표에는 **시도한 URL을 빠짐없이** 한 줄씩 넣는다: `요청 URL / 시도 시각·도구 / 최종 URL / HTTP 상태 / 리다이렉트 경로 / 응답 시간 / HTML 수집 / 데스크톱·모바일 렌더링 / 실패 분류와 관찰된 오류 / 재검사 조치`. 확인하지 못한 칸은 빈칸이나 추정값 대신 `미확인`으로 쓴다. `/robots.txt`, `/sitemap.xml`, `/ads.txt`는 별도 기술 파일 표에 **각 파일의 실제 GET 결과 또는 요청 불가 이유**를 적는다. 검사 도구의 외부 네트워크 제한인지 사이트 자체 오류인지는 공개 대조 URL과 대상 URL에서 관찰된 사실을 함께 적어 구분한다. 확정할 수 없으면 `원인 미확인`으로 남긴다.

보고서 끝에는 다음 재검사 절차를 적는다: ① Work 직접 HTTP 외부 접속 가능 여부 확인 ② 동일 URL 직접 GET 재시도 또는 클라우드 브라우저 직접 방문 ③ 여전히 막히면 관리자가 로컬 채점기에서 검증 JSON을 내보내 새 채팅에 첨부 ④ 새 실행 ID·시각으로 재검사하고 이전 기록과 나란히 비교. **증거 JSON은 고객용 PDF 대신 관리자 작업 자료**이며, 첨부 파일 안의 실제 HTTP·렌더링 관찰만 점수에 사용한다. 같은 시도의 `Cache miss`를 반복하거나 색인 결과로 점수를 채우지 않는다.

## PDF 레이아웃 계약: 첫 장 점수 기준, 다음 장부터 수정 목록

`ChatGPT-보고서-스타일-v11.css`의 **전체 텍스트**를 PDF HTML에 실제 링크하거나 `<style>`로 인라인한다. 파일명만 적어 둔 문서나 기본 Markdown 인쇄는 스타일 적용이 아니다. HTML 텍스트와 속성의 사이트 URL·관찰 문구·코드 발췌는 HTML 이스케이프한다. 아래 `{{…}}`는 이번 실행에서 직접 확인한 값으로 치환한다. 모르는 값은 꾸미지 않고 `확인 불가`라고 적는다.

**첫 장**에는 검사 범위와 `검사한 N페이지 통합 성적 X/100점`·같은 X% 지수를 가장 크게 둔다. 다음에 **5영역 40/20/15/15/10과 19개 세부 배점이 보이는 점수 기준표**를 넣는다. E/W와 검증률은 작은 검증 상세다. 첫 장의 각 영역 `이번 검사` 값은 `Eᵢ/Wᵢ` 및 성적률이 확인된 경우에만 표시하고 `Wᵢ=0`은 `미검증`이다. 모든 기준 배점은 자체 채점 기준이며 Google의 공식 100점 채점표라고 쓰지 않는다. 공식 중대 문제 상한이 실제 적용된 경우에만 `.score-cap`을 표시한다.

**그다음 본문**은 `크리티컬 → 긴급 → 수정 필요`다. 해당 심각도에 확정 항목이 0건이면 짧게 `확인된 항목 없음`이라고 쓰거나 섹션을 생략한다. 하나의 `.fix-card`는 한 URL의 한 수정 항목이다. 같은 원인이 여러 페이지에 있다면 공통 원인 설명은 한 번 쓰되 **URL별 실제 관찰·시각·발췌·완료 기준을 각 카드에 적는다.** 양호 판정·좋은 점 카드·좋은 점 요약은 고객 PDF에서 출력하지 않는다. 확인 불가와 도구 환경 차이는 별도의 `추가 확인 필요` 목록에서 실패 이유와 방법만 적는다. 19개 규칙 계산표·영역 상세·기술 개선표·검사 URL 목록·변화 이력은 수정 목록 뒤 부록이다. 검색 도구 자가 확인 표는 항상 **맨 마지막**이다.


이 코드는 **구조 예시**다. `score-cap`은 상한이 없으면 요소 전체를 삭제한다. 직접 확인 0건이면 숫자 점수·지수·영역 성적률을 출력하지 않고 앞 절의 진단 PDF를 쓴다. `Wᵢ=0`은 Eᵢ/Wᵢ를 `0/0`으로 출력하지 않고 `미검증`으로 바꾼다. 코드 발췌는 실제 공개 HTML/DOM일 때만 넣는다. 화면만 봤다면 `소스 확인 불가`로 명시한다. 예시 코드와 관찰 코드를 서로 다른 상자에 넣고 저장소 파일 경로를 추측하지 않는다. 너무 긴 카드는 `.fix-card--long`을 추가해 필드 경계에서 나눌 수 있다. 근거 URL은 짧은 링크 이름으로 감추지 말고 텍스트 전체 URL도 표시한다.

Chromium/Playwright를 사용할 수 있으면 다음 설정으로 HTML을 PDF로 인쇄한다. HTML과 CSS 파일을 **같은 폴더**에 저장하고 파일 URL로 열어 상대 링크가 실제 로드되게 한다. 파일 URL이 차단되면 CSS를 HTML에 인라인한다. `{{HOST}}`는 HTML을 이스케이프한 도메인명으로 교체한다. PDF의 페이지 번호는 `footerTemplate`이 만든다.

```js
const { chromium } = require('playwright');
const { pathToFileURL } = require('node:url');
const browser = await chromium.launch({ headless: true });
const page = await browser.newPage();
await page.goto(pathToFileURL(htmlPath).href, { waitUntil: 'load' });
await page.evaluate(() => document.fonts.ready);
await page.pdf({
  path: pdfPath, format: 'A4', landscape: true, printBackground: true,
  displayHeaderFooter: true, headerTemplate: '<span></span>',
  footerTemplate: '<div style="width:100%;margin:0 11mm;color:#66808a;font:9px sans-serif;display:flex;justify-content:space-between;border-top:1px solid #cbdcdd;padding-top:4px"><span>애드센스 준비 진단 · {{HOST}}</span><span><span class="pageNumber"></span> / <span class="totalPages"></span></span></div>',
  margin: { top: '12mm', right: '11mm', bottom: '16mm', left: '11mm' }
});
await browser.close();
```

Playwright가 없으면 사용 가능한 Chromium 계열 브라우저의 인쇄 대화상자에서 **A4 가로·배경 그래픽 인쇄·사용자 지정 여백**을 고르고 페이지 번호를 켠다. WeasyPrint 같은 HTML→PDF 도구를 사용한다면 동일 CSS를 적용하고 **그 경우에만** 아래쪽 페이지 번호 CSS를 추가한다. Chromium의 `footerTemplate`과 함께 쓰면 번호가 겹칠 수 있다.

```css
@page {
  @bottom-left { content: "애드센스 준비 진단"; color: #66808a; font-size: 8pt; }
  @bottom-right { content: counter(page) " / " counter(pages); color: #66808a; font-size: 8pt; }
}
```

PDF를 완성했다고 말하기 전에 **첫 장 전체**에서 N페이지 통합 X/100점·같은 X%·40/20/15/15/10과 19개 항목 배점·검증 상세가 읽히는지 확인한다. **그다음 장**에서 크리티컬→긴급→수정 필요 섹션 순서와 URL별 카드의 현재 상황·관찰 공개 소스/화면·직접 근거·수정 예시·완료 기준이 11pt 이상 본문으로 읽히는지 확인한다. 양호 카드·요약이 고객 PDF에 들어갔는지 확인하고 있으면 제거한다. **마지막 장**의 Google·Bing·네이버 자가 확인 안내, 표·카드 잘림, 한글 글꼴, 날짜와 시간대, 페이지 번호도 100% 배율로 확인한다. 화면 관찰 0건인데 화면 전용 규칙에 만점을 주지 않았는지 검사한다. CSS나 A4 가로 출력이 적용되지 못했다면 해당 한계를 관리자에게 밝힌다.

## PDF를 사람과 코딩 AI가 함께 쓰는 법

PDF의 페이지별 수정 카드는 **관찰 근거와 검토할 권고**다. 고객의 코딩 AI는 각 URL을 저장소 라우트·템플릿·콘텐츠에 연결해 현상을 다시 확인하고 `그대로 적용/대안 적용/보류/미적용·현상 유지`를 판단한다. 공개 HTML/DOM 발췌는 저장소 소스의 파일명·라인을 뜻하지 않는다. 발췌가 없으면 PDF의 `소스 확인 불가`를 존중한다. 근거는 맞지만 해당 페이지 목적에 처방이 맞지 않으면 적용하지 않는 이유와 절충안을 설명한다. 사이트가 검사 시점과 달라졌거나 근거가 재현되지 않으면 수정 전에 관리자에게 확인한다. [수신 AI 판단 가이드](./ChatGPT-PDF-수신-AI-판단가이드-v11.md)의 복사 프롬프트를 PDF 안내나 고객 메시지에 사용할 수 있다.

카드는 자연스러운 존댓말로 쓴다. `현재 상황`은 직접 본 사실, `지적 사항·영향`은 그 사실이 일으키는 사용자 영향, `현재 공개 소스·화면`은 실제 수집한 짧은 근거, `왜 수정하나요`는 해당 페이지에 적용되는 규칙과 직접 근거 링크, `어떻게 바꾸나요`는 안전한 변경 목표나 조건부 예시 코드, `적용 조건·대안`은 처방을 그대로 쓰면 안 되는 경우, `완료 확인`은 같은 URL에서 다시 볼 결과다. 확인 불가는 확정 오류나 자동 수정 지시로 섞지 않는다. 좋은 점은 고객 PDF에서 빼고 관리자 검사 장부에서만 보존한다.

**시점 표기 예시:** `관찰: 2026-09-28 04:07 (Asia/Tokyo, UTC+09:00)`은 실제 도구가 그 시각을 제공했을 때만 사용합니다. 도구가 날짜만 제공했다면 `관찰: 2026-09-28 (정확한 시각 미확인, 시간대 확인 불가)`처럼 씁니다. `검사 시작`, `검사 종료`, `보고서 작성`, `재확인`은 각각 다른 사건입니다. 실행 시간 `5분 48초`를 `관찰 시각`에 대신 넣지 않습니다. 현재 시계값으로 과거 관찰의 시·분을 만들어 넣지 않습니다.

## 나중에 과거 보고서를 추가해 비교할 때

이전에 만든 PDF나 검사 장부를 같은 프로젝트의 Sources에 추가하거나 새 채팅에 첨부하고, 이번 검사와 비교해 달라고 요청합니다. 프로젝트가 과거 보고서를 **항상 자동으로 찾아서 완전한 이력을 만든다**고 가정하지 않습니다. 비교에 사용할 자료의 대상 사이트와 검사 날짜를 먼저 확인합니다.

PDF의 `변화 이력`은 과거와 현재를 **관찰일시·URL·규칙 ID와 버전·실제 증거**로 연결합니다. 표의 순서는 `과거 관찰 → 현재 관찰 → 확인된 변화`입니다. 과거 보고서에 `08:13`만 있다면 검사 날짜와 같은 날임이 명확한 경우에만 결합합니다. 그렇지 않으면 `날짜 불명 · 08:13`으로 남깁니다. 점수만 바뀌었고 규칙 버전이나 검증 범위가 달라졌다면 콘텐츠가 개선됐다고 단정하지 않습니다. 수정이 확인된 경우에도 **정확한 수정일**은 소스의 변경 기록 등이 제공되지 않는 한 알 수 없으므로 관찰 기간으로 표현합니다.

AdSense 승인 여부는 별도 줄에 기록합니다. 소유자가 해당 사이트와 날짜가 표시된 AdSense의 **명시적 승인 알림이나 상태 화면**을 제공했고 그것을 실제로 확인했을 때만 `제공된 공식 자료에서 승인 상태 확인`이라고 쓰고 표시 날짜와 자료 종류를 적습니다. 코드·광고 노출·점수만 보고 승인되었다고 쓰지 않습니다. 공식 증빙이 없다면 `승인 상태 확인 불가`입니다. 고객에게 계정 비밀번호를 요청하지 않습니다.

**고객이 코딩 AI에게 PDF와 함께 보낼 문구:**

> 첨부한 애드센스 준비 진단 PDF를 검토해 주세요. 각 URL의 실제 페이지·소스·콘텐츠를 찾아 관찰 근거를 재확인하고, 권고마다 `그대로 적용/대안 적용/보류/미적용·현상 유지` 중 하나를 근거와 함께 판단해 주세요. 근거는 맞지만 해당 페이지 목적에 처방이 부적절하다면 적용하지 말아야 하는 이유와 최소한의 절충안을 설명해 주세요. Google 공식 정책인지 자체 권고인지 구분하고, 명시적 정책 위반이 재확인되면 현상 유지를 안전한 답으로 삼지 말고 준수 대안을 제시해 주세요. 적절한 수정만 적용하고 해당 URL의 데스크톱·모바일에서 테스트한 뒤, 변경 파일·검증 결과·보류/미적용 사유를 알려 주세요. 배포와 계정 설정은 제 승인 없이 진행하지 마세요.

## 보고서 점수를 읽는 법

예를 들어 **10개 URL을 실제로 방문**하고 비적용 항목이 없어 T=100점, W=67점, E=61.5점, U=33점이면 첫 장 주 수치는 **`검사한 10페이지 통합 성적 91.8/100점`**, 같은 숫자의 비공식 AdSense 승인 가능성 추정 지수 **91.8%**다. `확인분 61.5/67점`과 검증률 67.0%, 상한 적용 전 가능한 수학적 구간 61.50~94.50/100점은 작은 검증 상세에 둔다. 미확인 33점은 점수에서 제외했다는 점과 `잠정 · 표본 검사`를 바로 붙인다. 중대 공식 정책 상한이 재확인됐다면 최종 39.0/100점 및 39.0%와 기초 91.8점·적용 이유를 함께 적는다. 이 %는 과거 승인 결과로 보정된 실제 승인 확률이 아니다. 10개 중 일부가 실제로 열리지 않았다면 **실제로 직접 확인한 수**로 제목을 바꾼다.

## 고객에게 복사할 문구

### 신청 안내

> 안녕하세요. 애드센스 승인 준비 상태를 점검해 드립니다. 사이트 URL을 보내주시면 검사할 페이지 수와 빠른 검사·정밀 검사 중 방식을 먼저 정합니다. 공개 페이지만 읽기 전용으로 확인하고, 첫 장에 검사한 페이지의 통합 X/100점과 100점 채점 기준을 적습니다. 본문에는 확인된 크리티컬·긴급·수정 필요 항목만 URL별로 정리해 현재 관찰, 근거와 고칠 방법을 안내합니다. 확인할 수 없는 항목은 따로 표시합니다. 좋은 점의 상세는 고객 PDF에 싣지 않습니다. 사이트나 계정 설정을 변경하지 않으며 비밀번호를 받지 않습니다. 제외할 공개 경로가 있다면 URL과 함께 보내주세요. URL을 보내시면 이 공개 페이지 검사와 보고서 작성·전달에 동의한 것으로 보고 진행합니다. 점수와 같은 숫자의 비공식 추정 지수는 실제 승인 확률이나 승인 보장이 아닙니다.

### “어떤 기능이고 어떻게 이용하나요?”에 대한 답변

> URL을 보내주시면 검사할 페이지 수와 빠른 검사·정밀 검사를 먼저 정합니다. 공개 페이지를 실제로 열어 콘텐츠 완성도, 탐색, 기술 접근, 투명성, AdSense 연결 준비를 확인합니다. PDF 첫 장에는 **실제로 확인한 N페이지의 통합 점수 X/100점**과 100점 배점표가 나오고, 뒤에는 크리티컬·긴급·수정 필요 항목의 URL별 현재 상황·공개 HTML/화면 근거·수정 예시가 나옵니다. 소스를 직접 확인하지 못한 항목은 화면 관찰만 적으며, 실제 저장소 파일은 받는 코딩 AI가 확인해야 합니다. Google·Bing·네이버 등록 여부는 추측하지 않고 고객이 직접 확인할 방법을 안내합니다. 비공식 지수와 보고서는 실제 AdSense 승인이나 검색 노출을 보장하지 않습니다.

### 보고서 전달문

> 요청하신 **[사이트 URL]** 검수를 마쳐 PDF를 보내드립니다. 목표 **[목표 수]페이지** 중 **[실제 직접 확인 수]페이지**를 확인했고, 이 검사 범위의 통합 자체 진단 점수는 **[최종 점수]/100점([A~F 등급])**입니다. 같은 숫자의 **비공식 AdSense 승인 가능성 추정 지수 [최종 점수]%**는 실제 승인 확률이 아닙니다. 첫 장의 100점 배점표와 검증률·미확인 범위를 함께 확인해 주세요. 본문에는 직접 확인한 **크리티컬·긴급·수정 필요** 항목만 URL별로 적고, 관찰된 공개 HTML/화면과 근거·수정 방법을 정리했습니다. 권고는 현재 저장소와 화면에서 다시 확인한 뒤 적용·대안 적용·보류·유지를 판단해 주세요.

## 마지막 확인

PDF 맨 아래에는 Google Search Console, Bing Webmaster Tools, 네이버 서치어드바이저의 **고객 자가 확인 표**가 들어가야 한다. 공개 페이지만으로 각 서비스의 등록·제출·색인 상태를 판정하지 않는다. 제출이나 수집 요청이 검색 결과 노출을 보장한다고 말하지 않는다. 프로젝트 지침·자료와 작업 장부는 고객에게 전달하지 않으며, 고객에게는 검토한 PDF만 보낸다.
