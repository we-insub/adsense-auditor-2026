# 애드센스 채점 PDF를 받은 코딩 AI의 판단 가이드

규칙 버전: **GPT-2026.09.29-11**. 이 문서는 보고서를 만드는 ChatGPT 프로젝트의 자료이자, 고객이 PDF와 함께 자신의 코딩 AI에게 전달할 지침이다. PDF는 **특정 시점의 공개 사이트 관찰과 권고**이지 저장소의 구현 상태나 Google 승인 결과를 보증하는 명령서가 아니다. 고객 PDF는 크리티컬·긴급·수정 필요의 확인된 수정 항목만 싣고, 양호 항목 상세는 포함하지 않는다.

## 작업 원칙

1. PDF에서 대상 사이트, **텍스트로 표시된 전체 최종 URL**, 관찰 날짜·시간대, 규칙 ID·버전, 관찰된 문구·화면 위치, 실제 확인 범위와 `확인 불가`를 먼저 읽는다. PDF 생성일을 관찰일로 바꾸지 않는다. 점수와 승인 상태는 수정 지시의 근거로 사용하지 않는다. 여러 URL을 묶은 카드라면 공통 설명 뒤의 **URL별 관찰·재현 여부**를 각각 확인한다.
2. 현재 저장소의 라우트·템플릿·콘텐츠와 공개 URL을 연결하고 데스크톱·모바일에서 현상을 재현한다. PDF의 `현재 공개 소스·화면` 발췌는 브라우저로 받은 HTML/DOM 또는 화면 문구일 뿐 저장소 파일·서버 코드가 아니다. URL에 대응하는 파일과 기술 스택을 실제 저장소에서 찾되 지어내지 않는다. `소스 확인 불가`라면 화면 관찰만 재현한다. 사이트가 바뀌어 재현되지 않거나 읽은 범위가 제한되면 `재확인 필요`로 둔다.
3. **관찰이 사실인지**와 **제시된 처방이 이 페이지에 적합한지**를 별도로 판단한다. 페이지의 목적, 독자, 법적·정책 의무, 콘텐츠 운영 방식, 디자인, 접근성, 현재 광고 배치를 확인한다. Google 공식 정책·권장사항·채점기 자체 기준을 구분하고 공식 문서의 해당 부분이 이 URL의 상황을 직접 다루는지 확인한다.
4. 각 권고를 `그대로 적용`, `대안 적용`, `보류`, `미적용·현상 유지` 중 하나로 분류한다. `미적용`이어도 **관찰 사실이 맞는지, 왜 이 처방을 현재 페이지에 적용하면 안 되는지, 어떤 조건에서 다시 고려할지**를 말한다. 대안이 있으면 사용자 목적을 살리는 최소 변경안을 제시한다. 단순한 취향이나 편의로 **확인된 명시적 Google 정책 위반**의 현상 유지를 안전한 선택이라고 말하지 않는다. 정책 위반이 불명확하면 사실·적용 정책을 재확인하고 확정 표현을 보류한다.
5. 근거가 충분하고 제약이 없는 수정은 진행하고 해당 URL에서 결과를 확인한다. 사업·편집 방침이나 법적 선택을 요하는 항목은 선택지·영향을 정리해 소유자/관리자에게 확인한다. 배포·계정 설정·광고 계정 변경은 명시적 승인 없이 진행하지 않는다.
6. 원래 PDF의 관찰·판정·점수·규칙 버전·관찰일을 소급해서 수정하지 않는다. `권고 결정`, 결정 이유·날짜, 실제 변경 파일, 변경 후 검증 시점을 별도 기록한다. 다음 검사에서 달라진 사실은 새 근거로 판정한다. 점수가 올랐다는 이유로 AdSense 승인을 주장하지 않는다.

## 점수 문구를 해석할 때

진단 PDF에서 `Cache miss`가 나오면 **검색 도구가 해당 URL의 캐시를 열지 못했다는 뜻**이다. 직접 HTTP 요청·브라우저 방문 결과가 없으면 사이트의 접속 장애, AdSense 크롤러 차단, 콘텐츠 문제로 옮겨 적거나 수정하지 않는다. `평가 불가`는 실측 근거 부족으로 점수를 보류했다는 뜻이며 0점이나 승인 확률 0%가 아니다. URL별 실패 분류와 검사 도구를 확인하고, 검사 환경 제한이라면 접속 가능한 환경에서 재검사한다. 관리자가 로컬 채점기의 증거 JSON을 제공한 경우에도 실행 ID·수집 시각·URL별 직접 HTTP/렌더링 결과를 확인하고 검색 색인 또는 이전 PDF의 추정값과 섞지 않는다. 이전 실행과 이번 실행의 도구·시각·URL·규칙 버전이 다르면 그 차이를 밝힌다.

PDF의 가장 큰 `검사한 N페이지 통합 성적 X/100점`은 실제 직접 확인한 N페이지 집합의 단일 점수다. 10페이지라고 1,000점 만점이 되는 것이 아니다. `확인분 E/W점`은 직접 확인한 규칙 배점에서 획득한 보조 검증 수치다. **잠정 자체 진단 총점 `S=100E/W`**는 이 확인분을 100점으로 환산한 값이다. 미확인 배점 `U`는 점수에 포함되지 않는다. `검증률 W/T×100%`는 적용 가능 배점 중 실제 측정한 비율이며, 미확인 이유와 함께 읽어야 한다. `비공식 AdSense 승인 가능성 추정 지수 S%`는 총점과 같은 숫자를 % 눈금에 올린 자체 휴리스틱이며, **실제로 AdSense 승인을 받을 통계적 확률이 아니다.** 공식 중대 정책 문제가 재확인되어 39점 상한이 적용되면 첫 장에 기초 S와 최종 S최종 및 근거가 나뉘어 표시된다. `전체 자체 점수 가능 구간 100E/T~100(E+U)/T`는 미확인 항목이 모두 0점 또는 모두 만점일 때의 **상한 적용 전 수학적 경계**다. 원점수 경계 `E~(E+U)점 (T점 만점)`도 함께 보아야 한다. 영역 `Wᵢ=0`은 F가 아니라 미검증이다. 단일 점수나 등급만으로 개별 코드 수정의 우선순위를 정하지 말고 URL별 관찰과 현재 코드·화면을 재확인한다. `T=0`, 직접 확인한 HTML·브라우저 문서 0개, `W=0`이면 PDF에 적힌 평가 불가 이유를 따른다.

## 항목별 답변 형식

| 필드 | 작성할 내용 |
|---|---|
| 페이지·규칙 | 최종 URL, 카드 제목, 규칙 ID·버전 |
| 이전 관찰 | PDF의 관찰 시점·화면 위치·짧은 원문·읽은 범위·실제 공개 HTML/DOM 발췌 여부 |
| 현재 확인 | 현재 코드와 URL에서 재현했는지, 확인한 증거·시각 또는 불확실한 이유 |
| 근거 평가 | PDF의 사실/정책 연결이 맞는지; Google 공식 정책·권장사항·자체 기준 중 무엇인지; 크리티컬·긴급·수정 필요 심각도가 재현 근거와 맞는지 |
| 적용 판단 | `그대로 적용 / 대안 적용 / 보류 / 미적용·현상 유지` |
| 왜 | 원 권고가 맞는 조건, 현재 페이지에 그대로 적용하면 해가 되는 이유 또는 재현 불가 이유 |
| 절충안 | 필요하다면 원래 문제와 페이지 목적을 함께 충족하는 최소 대안; 어려우면 이유와 필요한 결정 |
| 결과·검증 | 실제로 찾은 저장소 파일·적용 범위, 해당 URL의 데스크톱·모바일 확인, 미변경 사유·재검토 조건 |

반복되는 공통 사항은 한 번 설명하고 영향받는 URL을 붙인다. `미적용`만 적고 이유를 생략하거나, 모든 카드에 같은 “상황에 따라 다름”을 복사하지 않는다. 사이트 맥락을 못 보면 가정과 필요한 질문을 구분한다.

## 판단 예시

- **짧은 문의 화면:** 본문이 짧다는 관찰은 맞아도 문의처·이용 방법이 명확한 화면에 기사 수준의 글을 넣으면 목적이 흐려질 수 있다. `content.empty`의 페이지 유형을 다시 검토하고, 필요한 연락 안내만 보강한다. 이 화면에 실제 광고가 게재되고 콘텐츠가 없다는 사실이 있다면 `adsense.emptyAds`를 별도로 검토한다.
- **의도적인 `noindex`:** 메타 태그 관찰이 맞아도 검색 결과·비공개 성격의 화면을 색인하려는 것은 아닐 수 있다. 소유자의 공개 범위와 SEO 목표를 확인한다. 핵심 공개 글만 잘못 `noindex`된 경우 그 페이지에서만 조정한다.
- **장식 이미지의 빈 `alt`:** 빈 `alt`가 관찰돼도 장식 이미지는 그대로 두는 것이 적절할 수 있다. 정보 전달 이미지인지 확인한 뒤 필요한 것만 설명한다.
- **AdSense 연결 흔적 부족:** 공개 페이지에서 코드를 보지 못한 것과 실제 계정 미승인은 다르다. 임의 코드를 넣기 전에 소유자가 현재 연결 방식과 공식 계정 상태를 확인한다.

## PDF와 함께 보낼 복사 프롬프트

> 첨부한 애드센스 준비 진단 PDF의 크리티컬·긴급·수정 필요 항목을 순서대로 검토하고 적절한 것만 수정해 주세요. 각 카드의 URL을 현재 저장소의 페이지·콘텐츠·공통 컴포넌트에 연결하고 PDF의 관찰 시점, 화면 문구, 공개 HTML/DOM 발췌를 현재 사이트에서 재확인해 주세요. PDF의 예시 코드는 실제 저장소 파일이나 구현이 아닙니다. 각 권고마다 **① 관찰이 지금도 맞는지 ② 해당 Google 공식 정책·권장사항 또는 자체 기준이 현재 페이지에 실제로 적용되는지 ③ 그대로 수정하면 안 되는 이유가 있는지 ④ 적용/대안 적용/보류/미적용 중 어느 선택이 맞는지 ⑤ 목적을 살리는 절충안과 확인 방법**을 설명해 주세요. 근거는 맞아도 처방이 부적절하면 무조건 고치지 말고, 왜 유지하거나 다른 방법을 택해야 하는지 구체적으로 적어 주세요. 확인된 명시적 정책 위반은 현상 유지를 안전하다고 말하지 말고 정책을 지키는 대안을 제시해 주세요. 바로 적용할 수 있는 수정만 진행하고 변경 파일과 데스크톱·모바일 검증 결과를 알려 주세요. 불명확한 사업·편집 선택은 선택지를 정리해 제 판단을 받아 주세요. 이전 PDF의 점수·관찰 이력은 고치지 말고 이번 결정과 변경 이력을 별도로 남겨 주세요. 배포·계정 변경은 제 승인 없이 하지 마세요.

## 고객에게 설명할 한 문장

> 보고서의 지적 사항은 검토할 근거와 권고입니다. 실제 사이트의 목적에 맞지 않는 권고는 적용하지 않아도 되며, 그 이유와 가능한 대안을 확인한 뒤 수정 여부를 정합니다. 확인된 Google 필수 정책 문제라면 정책을 지키는 방법을 찾아야 합니다.
