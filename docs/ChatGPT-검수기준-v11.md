# 2026 구글 애드센스 채점기 — 검수기준

규칙 버전: **GPT-2026.09.29-11**. 이 문서는 어떤 공개 사이트에도 적용하는 관리자 ChatGPT 프로젝트의 자료다. Google의 승인 기준표가 아니라 공개 페이지를 일정한 방식으로 살피기 위한 자체 점수표다. 공식 도움말의 최신 내용과 실제 AdSense 계정 알림은 검사할 때 다시 확인한다. **200페이지는 Google의 최소 게시물 수가 아닌 검수 범위 기준**이다.

**관찰·채점과 수정 결정을 분리한다.** PDF에 적힌 현상이 사실이어도 권고안을 그대로 적용하는 것이 해당 페이지의 목적, 접근성, 운영 방식, 법적 고지 또는 다른 기능에 불리할 수 있다. 수신자가 합당한 이유로 권고를 적용하지 않더라도 과거 관찰 기록을 지우거나 당시 점수를 임의로 바꾸지 않는다. 이후의 실제 상태는 새 관찰 시점과 근거로 다시 판정한다.

## 직접 접속 증거와 검사 환경 진단

`검색 결과·색인·캐시`는 후보 발견에만 쓴다. `Cache miss`는 검색 도구의 자료 부족이지 대상 사이트의 HTTP 오류가 아니다. 직접 HTTP GET으로 받은 HTML이나 실제 브라우저 주소창에서 연 렌더링 문서에 한해 `직접 확인 페이지`로 센다. 각 URL마다 `실행 ID / 요청 URL / 시도 시각과 사용 도구 / 최종 URL / HTTP 상태 / 리다이렉트 경로 / 응답 시간 / HTML 수집 여부·바이트 수 / 데스크톱·모바일 렌더링 / 제목·본문·오류 화면 / 스크린샷 또는 미생성 사유 / 실패 분류·오류 원문`을 저장한다. 도구가 제공하지 않는 필드는 `미확인`으로 남긴다. 브라우저에서 페이지가 보였다는 사실만으로 HTTP 200이나 원본 HTML 확보를 주장하지 않는다.

같은 사이트의 `/robots.txt`, `/sitemap.xml`, `/ads.txt`는 페이지와 분리해 각각 직접 GET한다. 상태코드·최종 URL·본문 존재 여부·요청 시각·실패 원인을 기록한다. 파일이 실제 HTTP 404로 확인된 경우와 검사 도구가 파일을 읽지 못한 경우를 구분한다. `robots.txt`의 크롤러 규칙도 원문을 읽고 해당 경로와 User-agent에 적용되는지 확인해야 판정한다.

실패 분류는 `DNS`, `TLS·SSL`, `타임아웃`, `실제 HTTP 4xx·5xx`, `robots 차단`, `브라우저 렌더링 실패`, `검사 환경 외부 네트워크 제한`, `대상 사이트 접속 실패`, `검색 캐시만 있고 직접 접속 실패`, `원인 미확인` 중 관찰된 증거에 맞는 것으로 쓴다. 직접 접속 재시도는 최대 두 번이며 시도별 결과를 보존한다. 검사 환경의 제한이나 자동화 차단 가능성은 사이트 전체의 장애나 Google 크롤러 차단으로 단정하지 않는다. `접속 성공 URL 수 / 실제 시도 URL 수`와 `HTML 수집 성공 수 / 직접 브라우저 문서 관찰 수`를 별개로 적는다.

직접 확인 페이지가 0개라면 **100점 총점·등급·비공식 승인 가능성 추정 지수를 표시하지 않는다.** 대신 첫 장에 `평가 불가: 직접 접속 증거 0건`과 주된 실패 분류를 쓰고, URL별 시도/실패 표, 기술 파일 검사 표, 검증된 규칙 수·전체 규칙 수, 미확인 이유, Work 네트워크 설정·클라우드 브라우저·로컬 증거 파일 중 실제 가능한 재검사 경로를 담은 `검사 환경 진단 PDF`를 만든다. 검색 스니펫이나 오래된 PDF로 실측값을 채우지 않는다. 과거와 재검사를 비교할 때는 별도 실행 ID·시각을 보존하고, 검사 환경 차이와 실제 사이트 변화를 구분한다.

## 판정과 계산

실제 확인한 사실에 따라 `양호(1)`, `주의(0.5)`, `문제(0)`, `확인 불가`, `해당 없음` 중 하나로 판정한다. **확인 불가는 실측에서 감점도 만점도 아니며 단일 점수의 분자·분모에 넣지 않는다.** `해당 없음`은 실제로 비적용을 확인했을 때만 쓴다. 단순히 열어 보지 못한 것은 확인 불가다. 사이트 공통 규칙은 확인한 증거로 한 번 판정한다. 페이지별 규칙은 방문한 적용 페이지의 수를 분모로 한다. 페이지 본문이 잘려 필요한 부분을 보지 못했거나 기술 자료를 못 읽었다면 그 페이지의 해당 규칙은 확인 불가다.

각 규칙의 100점 가중치 중 **검증 가중치 W**와 **획득 E**를 계산한다. 페이지별 규칙의 적용 페이지 수 `n`은 방문한 페이지 중 **측정 또는 확인 불가**인 페이지 수다. 확인된 비적용 페이지는 `n`에서 뺀다. 측정된 페이지 수 `m`, 측정 판정 값의 합 `s`, 규칙 가중치 `w`라면 `Wᵣ=w×m/n`, `Eᵣ=w×s/n`, `Uᵣ=w−Wᵣ`이다. 예를 들어 적용 대상 30페이지 중 10페이지만 확인했다면 해당 가중치의 10/30만 검증한 것이다. `n=0`으로 전 페이지가 비적용이라고 확인된 경우에만 `Aᵣ=w`로 둔다. 사이트 공통 규칙은 측정 시 `Wᵣ=w`, 확인 불가 시 `Uᵣ=w`, 확인된 비적용 시 `Aᵣ=w`다. 규칙을 합산해 `T = 100-A`, `U = T-W`, **검증률 = W/T × 100**, **확인분 득점률 = E/W × 100**, **적용 배점 기준의 원점수 가능한 구간 = E ~ (E+U)점 (T점 만점)**, **전체 자체 점수의 100점 환산 가능한 구간 = 100E/T ~ 100(E+U)/T**로 계산한다. `E`·`W`·`A`·`T`·`U`는 계산 가능한 원래 자릿수를 유지하고 `W+U+A=100`을 검산한다. 규칙별 `적용 페이지 수/측정 페이지 수/판정/획득 E/검증 W/미확인 U/비적용 A`를 합산표로 제시한다.

**선택한 검사 집합의 통합 성적:** 10페이지를 실제 방문했다면 그 10페이지의 규칙별 결과를 합산해 **하나의 X/100점**을 낸다. 각 페이지의 점수를 단순 합산해 1,000점 만점으로 만들지 않는다. `E/W`는 검증된 규칙 가중치의 획득/배점이며 고객에게 보이는 총점이 아니다. 첫 장의 주 점수 라벨은 `검사한 N페이지 통합 성적 X/100점`으로 쓰고 N은 목표 수가 아닌 실제 직접 확인한 고유 페이지 수로 채운다.

**성적표의 단일 수치는 직접 확인한 HTML 또는 브라우저 문서가 하나 이상이고 `T>0`, `W>0`이면 계산한다.** 기초 잠정점수는 확인된 항목의 획득·배점만으로 **`S = 100×E/W`**이며 소수 첫째 자리까지 표시한다. 미확인 배점 `U`는 점수에 넣지 않고 검증률·미확인 이유·가능한 전체 점수 구간에만 쓴다. `U>0` 또는 검사 대상 URL 일부가 미방문이면 `잠정 · 표본 검사`를 점수·지수 바로 옆에 붙이고, 이 값이 확인분 성적이며 사이트 전체를 확정 평가한 결과가 아님을 밝힌다. `T=0`, 직접 확인한 HTML·브라우저 문서 0개, 또는 `W=0`인 세 경우에는 단일 수치와 추정 지수를 `평가 불가`로 표시하고 어떤 증거가 없어 계산할 수 없는지 적는다. 숫자 `0`으로 대체하지 않는다.

**공식 중대 문제 상한:** 실제 재방문에서 확인한 사실이 현재 적용되는 Google의 명시적 필수 정책을 위반한다는 근거가 있고, 해당 사실·정책 문구·출처 URL·관찰 시각을 연결한 `중대 문제`인 경우에만 최종 잠정점수 `S최종=min(S,39)`를 적용한다. 도구 오류, 가설, Google 권장사항, 채점기 자체 기준, 현재 적용 여부를 확인하지 못한 정책은 상한 사유가 아니다. 첫 장에는 상한 적용 전 `S`, 적용 후 `S최종`, 근거가 된 규칙 ID·URL·정책 링크와 이유를 모두 적는다. 이용자에게 보이는 **자체 진단 총점과 비공식 AdSense 승인 가능성 추정 지수는 둘 다 `S최종`과 같은 숫자**다. 상한을 적용하지 않으면 `S최종=S`다. 등급은 표시한 최종값으로 정하며 `A≥90`, `B≥80`, `C≥70`, `D≥60`, `F<60`이다. 먼저 원 자릿수로 계산하고 마지막에 소수 첫째 자리로 반올림한 **표시 점수**를 등급 경계에 적용한다. 검증률·확인분 득점률은 소수 첫째 자리, 환산 구간 양 끝은 소수 둘째 자리까지 표시한다. 가능한 점수 구간은 미확인 모두 0점/만점인 **상한 적용 전의 수학적 범위**이므로 중대 상한 적용 후 표시 총점과 다를 수 있다. 그 차이를 설명한다.

**5영역 성적표:** 콘텐츠·완성도 40, 탐색·사용성 20, 공개 접근·기술 15, 투명성 15, AdSense 연결 준비 10의 명목 만점을 고정한다. 각 영역의 `Aᵢ,Tᵢ=명목 만점−Aᵢ,Wᵢ,Eᵢ,Uᵢ`를 위와 똑같이 합산한다. 열은 **영역/명목 만점/적용 Tᵢ/직접 확인 Wᵢ/확인 획득 Eᵢ/미확인 Uᵢ/미확인 이유 요약/확인분 성적률·등급 또는 상태**다. `Wᵢ>0`인 영역의 성적률은 `100Eᵢ/Wᵢ`이며, `Wᵢ=0`인 영역은 `미검증`으로 표시하고 F등급을 매기지 않는다. `Tᵢ=0`인 영역은 확인된 비적용으로 표시한다. 합계 행의 명목 만점 100과 T/W/E/U의 합이 첫 장 숫자 및 수식과 일치해야 한다. **전체 기초 S는 `100×ΣEᵢ/ΣWᵢ`이며, 각 검증된 영역 성적률을 `Wᵢ/W`로 가중 합산한 값**이다. 영역별 미확인 사유를 짧게 붙인다. 공식 중대 문제 상한을 적용하면 기초 S와 최종 S최종의 차이를 별도 주석으로 설명한다.

**추정 지수와 실제 확률을 구분한다.** 첫 장에 `비공식 AdSense 승인 가능성 추정 지수 S최종%`를 총점과 나란히 크게 표시한다. 이는 직접 확인한 공개 페이지의 자체 점수를 0~100% 눈금으로 표현한 **비공식 휴리스틱**이며, 과거 승인 사례로 보정한 통계적 승인 확률·Google의 심사 결과가 아니다. `실제 승인 확률은 이 검사만으로 검증할 수 없음`을 한 문장으로 붙이되 직접 근거로 계산한 수치형 자체 지수까지 없애지 않는다. 검증률과 가능한 전체 점수 구간을 함께 표시해 미확인 범위를 숨기지 않는다. 고객용 제목과 첫 페이지에는 항상 `표본 검사`를 쓰고, 관리자가 선택한 목표 방문 수·실제 방문 수·실패 수를 나란히 적는다. 발견 후보 수는 확인한 후보 URL 수이며 사이트 전체 확정 페이지 수가 아니다.

## 증거 장부와 재검증

1. URL을 직접 HTTP GET 또는 브라우저로 실제 연 경우에만 `방문`으로 세고 요청·최종 URL, 확인 가능한 검사 연·월·일·시각·시간대, 페이지 유형, 사용 도구, HTTP 상태·리다이렉트·응답 시간·HTML 존재 여부와 확인한 본문 범위·잘림 여부를 적는다. 검색 결과·사이트맵·다른 페이지의 링크에 보인 주소는 `후보`다. 상태 코드를 직접 못 봤으면 `HTTP 상태 확인 불가`라고 적는다. 도구 차단·시간 초과는 사이트 자체 오류로 단정하지 않는다.
2. 각 판정에 짧은 관찰 인용이나 화면 요소, 출처 URL, 가능한 줄 번호·제목·화면 위치를 붙인다. 인용과 URL이 맞는지 직접 대조한다. 타 사이트 문장이나 이전 검사에서 본 문장을 이 페이지 증거로 쓰지 않는다. 본문 일부만 제공된 경우 확인하지 못한 부분의 부재를 주장하지 않는다.
3. 첫 방문 후 내용이 바뀔 수 있다. 날짜·가격·진행 기간 등 변동 정보와 우선 수정 대상으로 올릴 중대한 결함은 보고서 생성 직전에 원본 URL을 다시 열어 확인한다. 재확인 실패·내용 변경·도구 사이의 상충은 `재확인 필요`로 격하하고 확정 결함 수에 넣지 않는다.
4. 원본 HTML과 렌더링된 화면을 구분한다. 컴퓨터 사용 기능이 가능하면 대표 페이지와 문제 페이지에서 데스크톱·모바일 화면을 각각 열고 제목·본문·오류 상태를 확인하며 가능하면 스크린샷을 보존한다. 렌더링 실패가 있어도 유효한 직접 HTTP HTML은 잃지 않고, 원본에서 직접 판정할 수 있는 규칙만 측정한다. 기능이 없으면 화면 의존 규칙은 확인 불가다. `robots.txt`, `sitemap.xml`, `ads.txt`, canonical, noindex, AdSense 연결 코드는 실제 파일·원본을 읽은 증거가 있어야 판정한다.
5. 아래 공식 링크는 최신 안내를 확인하는 출발점이다. 링크가 규칙의 숫자·승인 가능성을 공식화하지 않는다. `Google 공식 정책`은 공식 문서의 해당 문장이 관찰된 사실을 직접 다룰 때만 쓴다. 나머지는 `Google 권장사항` 또는 `채점기 자체 기준`으로 표기한다.
6. **화면을 확인하지 못한 규칙에 만점을 주지 않는다.** 예를 들어 렌더링 화면 관찰 0건이라면 `content.promotion`이나 `navigation.mobile`의 `Wᵣ=0`, `Uᵣ=w`다. 다른 규칙에서 본 링크·본문을 화면 관찰의 대용 증거로 바꾸지 않는다. 이전 PDF의 점수나 기억만으로 이번 관찰 장부를 채우지 않는다.
7. 현재 프로젝트의 규칙 원문·CSS를 실제로 읽지 못했다면 이전 PDF에서 규칙을 재구성해 현행 버전 보고서를 만들지 않는다. 관리자에게 누락 자료를 알리고 이번 버전의 PDF 생성은 중지한다. 과거 PDF는 날짜순 비교 자료로만 쓴다.

### 날짜와 변화 이력 기록

- 보고서 첫 장에 `검사 시작`, `검사 종료`, `보고서 작성`을 **서로 다른 값**으로 적는다. 각 카드의 `현재 상황`과 `근거·이유`에는 그 근거를 **실제로 관찰한 시점**을 연결하고, 다시 열어 확인했으면 `재확인 시점`도 별도로 적는다. 실행 소요시간은 시각이 아니므로 따로 표시한다.
- 시각을 확인한 경우에는 `YYYY-MM-DD HH:mm:ss (Asia/Tokyo, UTC+09:00)`처럼 **연·월·일·시·분·가능한 초·시간대**를 적는다. 예시는 형식 설명일 뿐 실제 관찰값으로 쓰지 않는다. 초가 없으면 분까지만 적는다. 날짜만 확인되면 `YYYY-MM-DD (시간대 확인 불가)`처럼 **알고 있는 정밀도까지만** 쓴다. 날짜와 시간대만 확인되면 `YYYY-MM-DD (Asia/Tokyo, 정확한 시각 미확인)`이라고 쓴다. 도구가 시각을 제공하지 않으면 현재 시각을 추정해 채우지 않는다. `08:13`이나 `오늘`만 단독으로 남겨 비교 가능한 절대시각인 것처럼 보이게 하지 않는다.
- 기기의 시간대나 도구가 제공한 시간대를 확인해 기록한다. 시간대 이름 또는 UTC 오프셋을 확인하지 못했다면 `시간대 확인 불가`로 둔다. 웹페이지 게시일, 검색 결과 표시일, PDF 파일 생성일, 채팅 메시지 시각을 **방문·관찰 시각**으로 바꿔 쓰지 않는다. 과거 PDF에 `08:13`만 있으면 그 PDF의 검사 날짜와 같은 날임이 명확할 때만 날짜와 합치고, 그렇지 않으면 `날짜 불명 · 08:13`으로 보존한다.
- 장부의 증거마다 `최종 URL`, `규칙 ID·버전`, `관찰 시점`, `화면·원문 위치`, `짧은 실제 문구/수치`, `판정`, `사용 도구·읽은 범위`, `재확인 시점 또는 미실시`를 연결한다. 공식 정책 페이지의 발행·수정일은 별개의 `근거 문서 날짜`다. 실제 확인하지 못하면 날짜를 넣지 않는다.
- 사용자가 이전 PDF나 검사 장부를 제공하면, 같은 사이트의 같은 최종 URL·페이지 유형·규칙 ID를 우선 맞춰 `이전 관찰 시점 → 이전 판정·증거 → 이번 관찰 시점 → 이번 판정·증거 → 확인된 변화` 순으로 **날짜순 변화 이력**을 만든다. 이전 URL이 이동했다면 확인한 이전·현재 URL의 연결을 표시한다. 규칙 버전, 검사 방식, 방문 범위, 읽은 본문 범위가 달라 비교가 어려우면 `직접 비교 어려움`이라고 적는다. 정확한 수정 날짜가 없으면 `이전 검사 이후~이번 검사 이전에 변화 확인`이라고만 쓴다. 이전 자료가 없다면 `이전 검사 자료 미제공: 이번 검사만 기록`이라고 쓴다. 프로젝트가 과거 채팅이나 PDF를 항상 자동으로 찾아준다고 가정하지 않는다.
- **AdSense 승인 이력은 점수 이력과 분리한다.** 광고 코드·광고 노출·준비도 점수 상승은 승인 증거가 아니다. 사이트와 상태·표시일이 연결되는 소유자 제공 AdSense 계정의 명시적 승인 알림·상태 화면 등 공식 기록을 실제 확인한 경우에만 그 자료에 적힌 상태와 날짜를 출처와 함께 적는다. 공식 기록이 없으면 `AdSense 승인 상태 확인 불가`로 표시한다. 승인 통지를 늦게 확인했다면 관찰일과 공식 기록의 표시일을 구분하고, 정확한 승인 시각을 추정하지 않는다. 비밀번호와 민감 계정 정보는 받지 않는다.

## 관찰 결과와 실제 수정 여부를 결정하는 법

관찰된 사실, 규칙에 따른 판정·점수, 수정 권고는 **서로 다른 층위**다. 예를 들어 특정 페이지의 본문이 짧다는 관찰은 사실일 수 있지만, 검색창·문의 화면에 긴 소개 글을 붙이라는 처방은 목적에 맞지 않을 수 있다. 보고서 작성자는 페이지의 실제 용도를 확인하고, 처방이 적절한지 별도로 논증한다. 코드·운영 목적·계정 설정을 못 봤다면 `현장 판단 필요`라고 적고 수정 지시를 확정하지 않는다.

| 권고 유형 | 보고서에 적을 내용 | 받은 사람·코딩 AI의 결정 |
|---|---|---|
| `확인된 문제·직접 개선 권고` | 재현된 현상, 현재 페이지에 왜 문제인지, 최소 수정안, 적용 전 확인할 제약 | 현재 코드와 화면에서도 재현되면 적용하고 재검증 |
| `조건부 개선` | 관찰은 맞으나 특정 목적·설정일 때만 문제가 되는 이유와 그 조건 | 조건을 확인해 적용·대안·현상 유지 중 선택 |
| `선택 개선` | UX/SEO/자체 점수표를 위한 제안임을 밝히고 얻는 효과와 바뀌는 비용 | 사이트 목표에 맞춰 선택하거나 보류 |
| `현상 유지 제안` | 왜 이 페이지의 현재 설계가 합당한지, 원래 권고가 부적절한 이유 | 변경하지 않고 근거와 재확인 조건 기록 |
| `추가 확인 필요` | 부족한 증거와 확인 절차 | 근거를 얻기 전 수정·정책 위반 확정 금지 |

- 카드에는 해당되는 경우에만 `적용 조건`, `그대로 적용하면 안 되는 이유`, `절충안`을 **페이지별 구체적 사실**과 연결한다. 무관한 예외·일반론을 모든 카드에 복사하지 않는다. 사이트 목적이 확인되지 않았으면 가능한 예외를 가설로 표기하고, `현상 유지`를 확정하지 않는다.
- 실제 선택지는 `그대로 적용`, `대안 적용`, `보류`, `미적용·현상 유지`다. 권고를 받는 코딩 AI는 현재 URL과 소스/렌더링 화면을 다시 확인한 다음 선택한다. 적용·미적용 각각의 이유와 검증 결과를 소유자에게 보고한다. 사업 목적이나 편집 방침에 관한 선택은 소유자·관리자가 최종 확인한다.
- Google의 **명시적 필수 정책과 현재 사실을 직접 대조해 위반을 확정**했다면, 편의나 취향을 이유로 `그대로 유지해도 안전`하다고 제안하지 않는다. 사실·정책 적용의 재확인과 **같은 목적을 달성하는 정책 준수 대안**을 분리해 제시한다. 공식 정책인지 불분명하거나 자료가 부족하면 위반이라고 확정하지 않는다.
- `미적용`은 `관찰이 거짓`이나 `점수 취소`를 뜻하지 않는다. 원래 근거와 판정, 규칙 버전, 관찰 날짜를 보존하고 `권고 미적용 사유`, 결정자, 결정일을 별도 이력으로 남긴다. 다음 검사에서 조건이 달라졌으면 새 증거로 재판정한다. 점수표의 자체 기준이 페이지 목적에 맞지 않아 보이면 **평가의 한계**를 명시하고 버전 변경 없이 과거 점수를 뒤에서 고치지 않는다.

### 적용 판단 예시

- `content.empty`: 문의 화면의 본문이 짧더라도 연락 방법과 사용 목적이 충분하면 일반 기사처럼 글을 늘리지 않는다. 실제로 게시자 콘텐츠가 없는 화면에 광고가 게재되는 문제는 별도로 확인한다. 절충안은 필요한 문의 안내만 추가하고 실제 광고 배치를 확인하는 것이다.
- `access.indexing`: `noindex`가 관찰되더라도 내부 검색 결과·감사 페이지처럼 공개 검색에 노출하지 않으려는 화면이라면 삭제를 요구하지 않는다. 공개 색인이 목표인 핵심 콘텐츠인지 소유자에게 확인하고, 목적에 맞는 페이지만 설정을 조정한다.
- 이미지 `alt`: 장식 이미지의 빈 `alt`가 합당할 수 있다. 실제 의미 전달 여부를 확인한 뒤 정보 이미지에만 설명을 넣는다.
- `adsense.connection`: 공개 원본에서 연결 코드를 보지 못했다는 사실만으로 사이트 미승인을 확정하거나 임의의 광고 코드를 삽입하지 않는다. 연결 방식과 공식 계정 상태를 소유자가 확인하도록 한다.

| `navigation.redirect` | 반복 리다이렉트 | 4 | 실제 이동 과정에서 불필요한 연쇄·루프를 확인한다. 한 번의 정상 이동은 문제로 보지 않는다. 도구가 이동 횟수를 보여주지 않으면 확인 불가로 둔다. | 자체 기준 · [Google 리다이렉트 안내](https://developers.google.com/search/docs/crawling-indexing/301-redirects) |

| `adsense.connection` | 사이트 연결 준비 | 7 | 실제 원본 HTML의 AdSense 코드·계정 메타 태그와 `ads.txt`의 확인 가능한 Google 판매자 행을 각각 기록한다. `ads.txt`만 확인된 경우 계정 연결까지 검증된 것으로 판정하지 않는다. 공개 흔적이 없어도 계정의 실제 연결 상태를 확정할 수 없고, `ads.txt` 부재만으로 승인 불가라고 하지 않는다. | [Google 연결 안내](https://support.google.com/adsense/answer/12131223?hl=ko) |

### 적용 범위와 판정 주의

- **페이지별 규칙:** `content.placeholder`, `content.empty`, `content.substance`, `content.duplicate`, `content.media`, `content.promotion`, `navigation.links`, `navigation.menu`, `navigation.redirect`, `navigation.mobile`, `access.response`, `access.render`, `access.indexing`, `adsense.emptyAds`. 방문 페이지의 유형과 실제 확인 범위를 따져 적용한다. 본문 비교처럼 여러 페이지의 자료가 필요한 규칙은 비교한 URL 쌍을 적는다.
- **사이트 공통 규칙:** `access.robots`, `trust.privacy`, `trust.identity`, `trust.notice`, `adsense.connection`. 공통 자료를 못 읽었다면 같은 추측을 방문 페이지 전부에 복제하지 않고 사이트 공통 항목 한 번만 확인 불가로 기록한다. `robots.txt`의 경로별 규칙은 실제 방문 경로와 대조한다.
- `해당 없음`은 비적용을 직접 확인한 경우에만 쓴다. 예컨대 미디어 중심이 아닌 페이지에서는 `content.media`가 해당 없을 수 있다. 광고가 아직 게재되지 않는 사이트의 광고 배치·쿠키 관련 쟁점은 현재 상태와 향후 준비 사항을 구분한다. 링크가 있다는 이유만으로 개인정보 안내의 내용이 충분하다고 단정하지 않는다.
- 방문한 페이지에서 `양호`를 준다 해도 사이트 전체의 모든 페이지·링크가 정상이라는 뜻은 아니다. 검사가 잘린 페이지, 미방문 링크, 다른 언어의 페이지는 표본 범위 밖이다.

## 관리자 확인 필요

광고 클릭 유도 문구와 실제 광고 배치, 외부 콘텐츠 권리·표절, 계정 중복, 결제·연령 요건, AdSense의 실제 심사 통보는 공개 URL만으로 확정할 수 없다. 소유자에게 Google 계정 비밀번호를 요청하지 않는다. Google의 [승인 불가 사유 안내](https://support.google.com/adsense/answer/81904?hl=ko)를 참고하되 실제 계정 알림은 소유자가 직접 확인한다.

## 고객용 PDF 구성: 통합 성적과 실행 가능한 수정 목록

**직접 확인 페이지 0개의 진단 PDF:** 숫자 점수와 추정 지수는 모두 `평가 불가`다. 이는 0점이 아니다. 첫 장에 `직접 확인 0 / 시도 N`, 직접 접속 실패의 정확한 분류·도구·시각, 점수를 낼 수 없는 이유와 재검사 순서를 쓴다. 시도 URL별 HTTP·HTML·브라우저 결과와 `/robots.txt`, `/sitemap.xml`, `/ads.txt`의 실제 GET 결과 또는 요청 불가 이유를 분리한다. `Cache miss`는 검색 캐시 실패일 뿐 사이트 HTTP 오류가 아니며, 검색 색인·이전 PDF로 점수를 채우지 않는다. 사이트 결함으로 확인되지 않은 항목은 수정 목록에 넣지 않는다.

### 첫 장: 100점 채점표와 통합 성적

- 맨 위에 대상 URL, 검사 시작·종료·보고서 작성 날짜와 시간대, 규칙 버전, 방식, 목표/발견/실제 직접 방문/실패 페이지 수를 쓴다. `실제 방문 10페이지`라면 가장 큰 숫자 카드에 **`검사한 10페이지 통합 성적 X/100점`**, 옆에 **`비공식 AdSense 승인 가능성 추정 지수 X%`**를 같은 숫자로 쓴다. X는 `S최종`이며 실제 승인 확률이 아니라 자체 준비도 지수다. 과거 승인 데이터로 보정하지 않았다. 등급·표본 표시를 붙인다. 실제 계정 심사 상태도 분리해 `확인 불가`로 둔다.
- 같은 첫 장에서 아래 **채점 기준표**의 다섯 영역, 명목 배점 40+20+15+15+10=100과 **19개 세부 규칙 이름·배점**을 전부 읽을 수 있게 표시한다. Google의 공식 점수표라고 표현하지 않는다. 각 영역의 실제 확인 성적은 점수 기준 옆이나 뒤의 5영역 성적표에 별도로 표시한다. PDF를 100% 배율로 열었을 때 표 글씨를 읽을 수 있어야 한다.
- 총점 아래의 작은 `검증 상세`에 `적용 T / 직접 확인 W / 획득 E / 미확인 U / 비적용 A`, `확인분 E/W`, 검증률 `100W/T%`, 가능한 점수 구간과 미확인 이유를 적는다. **E/W를 총점 카드처럼 크거나 앞에 배치하지 않는다.** U>0 또는 목표 일부 미방문이면 `잠정 · 표본 검사`라고 표시한다. 39점 상한이 실제 적용됐다면 기초 S와 최종 S최종, 재확인된 URL·규칙 ID·현재 정책 원문·링크·시각을 함께 적는다. 가능한 구간은 상한 적용 전 수학적 경계라고 표시한다.

|---|---:|---|
| 콘텐츠·완성도 | 40 | 미완성 문구 8 · 빈 본문 8 · 실질 콘텐츠 8 · 내부 중복 6 · 미디어·제휴의 자체 설명 6 · 콘텐츠와 홍보 균형 4 |

### 본문: 심각도 순서와 페이지별 수정 카드

확인한 문제를 **`크리티컬 → 긴급 → 수정 필요`** 순서로 나누고, 각 섹션 안에 **최종 전체 URL별** 항목을 나열한다. 판정 `양호`의 상세·좋은 점·양호 페이지 목록은 **고객 PDF에서 출력하지 않는다.** 관리자 장부에는 보존한다. 문제를 발견하지 못한 페이지에 빈 수정 카드를 만들지 않는다. 범위 확인용 검사 URL 목록은 필요하면 부록에 두되 양호 평가문은 싣지 않는다. 서로 다른 URL의 관찰·날짜·코드 발췌를 한 카드에 뒤섞지 않는다. 공통 원인은 한 번 설명한 뒤 영향을 받은 **URL별 관찰 행**을 따로 둔다.

- **크리티컬:** 실제 일반 사용자에게 중대한 접근 불가가 재현됐거나, 해당 URL의 현재 사실이 Google의 **적용 가능한 명시적 필수 정책**에 위반된다고 재방문과 정책 원문으로 확인했을 때만 쓴다. `39점 상한`은 이 중에서도 공식 필수 정책 위반이 확인된 경우에만 적용한다. 점수가 낮다는 이유만으로 크리티컬이 되는 것은 아니다.
- **긴급:** 주요 화면·기능에 중대한 영향이 있거나 여러 핵심 페이지에 걸쳐 반복된 결함을 직접 확인했지만 크리티컬 조건에는 이르지 않은 경우다. 사용자 영향·재현 URL을 적는다.
- **수정 필요:** 직접 확인한 나머지 문제·주의다. SEO 권장사항과 채점기 자체 기준은 정책 위반이라고 표현하지 않는다. 불확실하거나 도구 환경에서만 재현된 현상은 여기에 확정 수정 지시로 넣지 않고 `추가 확인 필요`로 둔다.

각 수정 카드는 사람이 읽고 코딩 AI가 해당 URL의 실제 저장소 파일을 찾아 고칠 수 있게 **서로 분리된 행**으로 다음을 적는다.

1. **페이지 주소·제목과 규칙:** 클릭 가능한 **전체 최종 URL**, 확인한 페이지 이름, 규칙 ID·버전, 심각도와 재현 상태.
2. **현재 상황:** 관찰 `YYYY-MM-DD HH:mm (시간대, UTC 오프셋)` 또는 `YYYY-MM-DD (정확한 시각 미확인)`, 화면·문서 위치, 직접 본 짧은 문구·수치. 검사 결과와 사이트의 실제 일반 사용자 상태를 구분한다.
3. **지적 사항·영향:** 확인된 사실로 사용자가 겪을 수 있는 영향. 전제가 필요한 영향은 `가능성`이라고 명시한다.
4. **관찰된 공개 소스/화면 근거:** 원본 HTML 또는 렌더링 DOM을 실제 수집했다면 **최소 1~3줄의 짧은 발췌**와 선택자·문서 위치, 확인 도구·시각을 적는다. 코드가 없고 화면만 확인했다면 `소스 확인 불가 · 화면에서 [문구/위치] 관찰`로 쓴다. 공개 HTML/DOM과 **서버 저장소 소스는 다르다.** 저장소에 접근하지 않았다면 내부 파일명·템플릿·프레임워크·원인을 지어내지 않는다. 발췌에는 비밀 값·개인정보를 포함하지 않고 HTML 특수문자를 이스케이프한다.
5. **왜 수정하는가·근거:** 관찰 사실과 현재 페이지에 적용되는 근거를 한 문장씩 연결한다. Google 공식 정책/Google 권장사항/채점기 자체 기준을 구분하고 직접 관련된 URL을 텍스트로 표시한다. 공식 문서가 그 페이지에 적용되지 않거나 해석이 불확실하면 위반 확정이나 크리티컬 표시를 하지 않는다.
6. **구체적 수정 예시:** 화면 또는 공개 HTML에서 무엇이 현재 어떻게 표시되는지와 목표 상태를 짝지어 설명한다. 수집한 공개 소스가 있을 때만 간단한 **전/후 코드 예시**를 제시하고 `예시 코드 · 실제 저장소 파일/구현 확인 필요`라고 표시한다. 실제 저장소의 파일 경로·라인과 수정 명령은 코딩 AI가 저장소를 본 뒤 결정한다. 안전한 코드 예시를 만들 근거가 부족하면 **수정 목표와 확인할 컴포넌트**만 적고 예시를 꾸미지 않는다.
7. **적용 조건·예외·대안:** 사실이 맞아도 제시된 수정이 페이지 목적에 맞지 않을 수 있는 조건, 그대로 적용하면 해가 되는 이유, 목적을 살리는 최소 대안을 해당 URL의 맥락과 함께 적는다. 확인하지 못한 조건은 질문으로 둔다. 명시적 필수 정책 위반이 재확인됐다면 단순 현상 유지를 안전한 선택으로 제안하지 않는다.
8. **완료 확인:** 수정 후 동일 URL의 데스크톱·모바일, HTTP/HTML/렌더링 중 해당 규칙과 관련된 결과를 어떻게 재검증할지 명시한다.

`확인 불가`는 심각도 목록과 시각적으로 분리해 `추가 확인 필요`에 실제 실패 이유, 확인 방법, 도구·시각을 적는다. 계정·표절·정책 적용 맥락 등 URL만으로 알 수 없는 사항은 관리자 확인 목록에 둔다. 19개 규칙 계산표, 비적용·미확인, 기술 개선표, 과거와 현재의 변화 이력은 부록에 둔다. 고객용 PDF에는 관리자 원본 장부나 내부 프롬프트를 넣지 않는다. **맨 마지막에는 Google·Bing·네이버 검색 도구 자가 확인 표와 등록 여부를 판정하지 않았다는 고정 안내**를 넣는다.

**PDF 수신 코딩 AI에게 보낼 문구:** “보고서의 URL과 관찰 시각을 기준으로 현재 저장소의 라우트·템플릿·컴포넌트를 찾아 공개 HTML/DOM 근거를 재확인하세요. 각 수정 항목에 대해 그대로 적용/대안 적용/보류/미적용 중 하나를 이유와 함께 선택하세요. 예시 코드는 실제 소스 경로나 확정 구현이 아니므로 현재 구조에 맞게 조정하고, 부적절한 권고는 이유와 절충안을 설명하세요. 적용한 변경은 해당 URL의 데스크톱·모바일에서 확인하세요. 배포·계정 설정은 소유자 승인 후 진행하세요.”

**최종 QA:** 첫 장의 `N페이지 통합 X/100점`과 동일 X%, 19개 기준의 100점 합계, E/W의 낮은 시각적 비중, 크리티컬·긴급·수정 필요 순서, URL별 현재 관찰·발췌·근거·수정 예시·완료 기준, 한글 글꼴과 11pt 이상 본문, 전체 URL과 링크, 마지막 검색 도구 안내를 실제 PDF 100% 배율에서 확인한다. 항목이 0건인 심각도 섹션은 생략하거나 `해당 없음`을 짧게 쓰되 문제를 지어내지 않는다. PDF를 만들거나 열어 확인하지 못했다면 완료라고 말하지 않는다.
