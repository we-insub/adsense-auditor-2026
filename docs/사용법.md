# 관리자 사용법 및 고객 응대 문구

## 고객 접수

아래 **고객 공지·신청 안내**를 복사해 보내고, 고객이 URL을 보내면 접수 메시지를 보관합니다. 공개 검사에서 제외할 경로가 있는지도 함께 받습니다. 비밀번호나 Google 계정 로그인 정보를 요청하지 않습니다. 고객에게 사이트를 변경하거나 검색엔진 등록을 대신한다고 안내하지 않습니다.

### 고객 공지·신청 안내

> 안녕하세요. 애드센스 승인 준비 상태를 점검해 드립니다. 사이트 URL을 보내주시면 로그인 없이 공개 페이지를 읽기 전용으로 검사합니다. 기본 검사는 최대 200페이지이고, 빠른 표본 검사는 최대 20페이지입니다. PDF 첫 장에는 실제 검사한 페이지 집합의 통합 자체 점수 X/100점과 100점 채점 기준을 보여드립니다. 본문에는 확인된 크리티컬·긴급·수정 필요 항목별로 페이지 주소, 현재 상황, 근거와 수정 방법을 적습니다. 확인할 수 없는 항목은 별도 안내합니다. 사이트나 계정 설정을 변경하지 않으며 비밀번호를 받지 않습니다. 200페이지를 넘는 사이트는 표본 검사로 표시하고 전체 검사는 별도 문의로 진행합니다.  
> 신청하실 사이트 URL과 검사에서 제외할 공개 경로가 있다면 함께 보내주세요. URL을 보내시면 이 검사 범위와 보고서 작성·전달에 동의한 것으로 보고 진행합니다. 비공식 승인 가능성 추정 지수는 자체 진단 점수와 같은 숫자이며 실제 승인 확률이나 Google 심사 결과는 아닙니다.

### “어떤 기능이고 어떻게 이용하나요?”에 대한 답변

> URL을 보내주시면 공개 사이트맵과 내부 링크에서 페이지를 찾아 기본 최대 200페이지를 검사합니다. 미완성 문구·빈 페이지·콘텐츠 중복, 링크와 메뉴, 모바일 화면, 검색 로봇 접근, 개인정보 안내, AdSense 연결 준비 상태 등을 확인합니다. PDF 첫 장에는 실제 검사한 페이지의 통합 점수 X/100점과 항목별 100점 배점표를 두고, 본문에는 크리티컬·긴급·수정 필요 항목의 URL별 현재 상황·공개 HTML/화면 근거·수정 방법을 적습니다. 사이트 저장소 코드를 직접 보지 못했다면 파일명이나 내부 구현을 추측하지 않습니다. 고객이 자신의 코딩 AI에 PDF를 전달해 재검토·수정할 수 있습니다. Google·Bing·네이버 검색 도구 등록 여부는 보고서에서 추측하지 않고 자가 확인 절차만 안내합니다. 실제 AdSense 승인과 검색 노출은 각 서비스의 판단에 따라 달라집니다.

빠른 표본 검사를 제안할 때는 기존의 기본 200페이지 공지만 보내지 말고, 아래 범위 안내를 고객에게 추가로 전달합니다.

> 빠른 표본 검사는 발견한 공개 페이지 중 최대 20페이지만 확인합니다. 결과와 점수는 검사한 페이지 범위에 대한 자체 진단이며, 사이트 전체 또는 기본 200페이지 검사의 결과와 같다고 볼 수 없습니다. 더 넓은 범위의 검수가 필요하면 기본 검사나 전체 검사를 요청해 주세요.

## 프로그램 실행

1. 관리자 Mac에 Node.js 24를 설치합니다. 작업 폴더에서 `npm install`과 `npx playwright install chromium`을 한 번 실행합니다.
2. `npm run dev`를 실행하고 터미널에 나오는 `127.0.0.1` 주소를 같은 Mac의 브라우저에서 엽니다. 로그인 없이 바로 사용할 수 있습니다.
3. 의뢰받은 URL을 입력합니다. 제외 경로가 있다면 해당 입력란에 추가합니다. 빠른 표본 검사는 최대 20페이지, 기본 검사는 최대 200페이지, 별도 전체 검사를 맡았다면 관리자 전체 검사를 선택합니다. 빠른 검사는 우선 확인용이며 고객에게 범위를 명시합니다.
4. 검사를 시작한 뒤 진행률과 발견·검사·실패 페이지 수를 확인합니다. 필요하면 일시 중지하고 나중에 재개합니다. 전체 검사는 사이트 규모에 따라 오래 걸릴 수 있습니다.
5. 완료되면 우선 수정 목록과 페이지별 판정표를 검토합니다. 접근 실패·확인 불가·오탐 의심 항목은 보고서 설명을 확인하고, 고객에게 확정 사실처럼 전달하지 않습니다.
6. HTML 미리보기에서 내용을 확인한 후 PDF를 내보내 고객에게 직접 전송합니다. 관리자 재검토용 HTML·JSON에는 사이트에서 수집한 내용이 들어갈 수 있으므로 공유 범위를 관리합니다.

개발용 실행은 `npm run dev`, 빌드 및 일반 실행은 `npm run build`와 `npm start`, 자체 검증은 `npm test`입니다. 프로그램은 사이트맵과 내부 링크로 **발견 가능한 공개 페이지**만 읽습니다. 로그인, 양식 제출, 사이트 수정, 검색엔진 계정 설정, 이메일 자동 전송은 수행하지 않습니다.

## 보고서 읽는 법

- **검사한 페이지의 통합 성적과 검증 범위:** ChatGPT 프로젝트 v11은 실제 방문한 N페이지의 규칙별 결과를 집계해 **하나의 X/100점**으로 표시합니다. 페이지당 100점을 더해 10페이지를 1,000점으로 만들지 않습니다. 직접 확인한 HTML 또는 브라우저 문서가 있고 T>0·W>0이면 `S=100E/W`이며, 최종 표시 점수 X와 같은 숫자의 비공식 AdSense 승인 가능성 추정 지수 X%를 첫 장에 보여줍니다. `E/W`는 검증 상세로만 표시합니다. 첫 장의 40/20/15/15/10 영역·19개 규칙 배점표가 점수 기준입니다. 미확인 U는 총점에서 제외하고 검증률·미확인 이유·가능 구간에 따로 표시합니다. 확인된 공식 중대 정책 문제에만 39점 상한이 적용될 수 있습니다. 직접 확인 0건·T=0·W=0이면 점수 대신 `평가 불가` 이유와 재검사 방법을 적습니다. `Cache miss`만으로 사이트 장애라고 판정하지 않습니다. X%는 실제 통계적 승인 확률이 아닙니다.
- **검사 범위:** 발견한 페이지 수, 실제 검사한 페이지 수, 접근 실패 수를 함께 읽습니다. 빠른 검사는 20페이지 표본 안내를 항상 표시합니다. 기본 검사에서 발견한 페이지가 200개를 넘으면 보고서 맨 위에 200페이지 표본 문구를 표시합니다.
- **페이지별 수정 카드:** 고객 PDF는 `크리티컬 → 긴급 → 수정 필요` 순으로 확인된 항목만 보여주며, 좋은 점·양호 항목 상세는 관리자 장부에만 남깁니다. 카드마다 전체 페이지 URL, 현재 상황과 관찰 시점, 짧은 공개 HTML/DOM 발췌(실제로 수집했을 때만), 왜 수정해야 하는지와 직접 관련된 근거 링크, 구체적 수정 예시, 예외·절충안, 완료 확인 방법을 서로 분리합니다. 원본 소스를 보지 못했다면 `소스 확인 불가`와 화면 관찰을 적습니다. PDF의 예시 코드는 고객 저장소의 실제 파일 경로나 내부 구현을 뜻하지 않습니다.
- **시점과 이력:** ChatGPT 프로젝트의 v11 보고서는 확인 가능한 관찰 연·월·일·시각·시간대를 각 근거에 연결합니다. 정확한 시각을 알 수 없으면 미확인으로 씁니다. 이전 PDF나 장부를 제공하면 URL·규칙별 변화를 날짜순으로 정리하되 실제 수정일과 AdSense 승인일은 증빙 없이 추정하지 않습니다. 권고의 적용·보류·미적용 결정은 관찰·점수 이력과 분리합니다. [ChatGPT 프로젝트 운영법](./ChatGPT-프로젝트-운영법-v11.md)을 참고하세요.
- **추가 기술 진단:** `<title>`, meta description, H1, `alt`, `lang` 같은 항목의 개선 제안입니다. 누락만으로 AdSense 공식 위반이라고 판단하지 않습니다.
- **관리자 확인 필요:** 저작권 허가, 콘텐츠 맥락, 계정 중복·결제·실제 심사 상태 등 공개 URL만으로 확정할 수 없는 항목입니다.
- **검색엔진 안내:** Google·Bing·네이버 도구에 사이트를 등록하거나 사이트맵을 제출했는지는 이 검사로 확인하지 않습니다. 안내는 고객이 직접 확인하도록 돕는 내용이며 AdSense 점수와 무관합니다. 사이트맵 제출이나 수집 요청도 실제 색인을 보장하지 않습니다.

일반적인 입력 요소의 `placeholder`는 검색어 등의 힌트이므로 미완성 문구로 판정하지 않습니다. 본문에 남아 있는 `Lorem ipsum`, `TODO`, ‘준비 중’, 템플릿 예문이나 제목만 있는 페이지가 미완성 신호입니다.

## PDF를 코딩 AI에 전달할 때

고객이 자신의 웹사이트 코드에 접근할 수 있는 코딩 AI에게 PDF를 첨부하고 아래 문구를 보낼 수 있습니다. 보고서는 **관찰된 웹페이지의 증거와 수정 권고**이며, 모든 권고를 그대로 실행하라는 뜻이 아닙니다. 저장소 안의 파일명이나 구현 기술을 미리 알고 작성한 문서도 아닙니다. [PDF 수신 AI 판단 가이드](./ChatGPT-PDF-수신-AI-판단가이드-v11.md)에 자세한 검토 절차가 있습니다.

> 첨부한 애드센스 준비 진단 PDF를 검토해 주세요. 각 URL의 현재 화면과 소스에서 관찰 근거를 재확인하고, 권고마다 `그대로 적용/대안 적용/보류/미적용·현상 유지` 중 무엇이 적절한지 이유를 알려 주세요. 근거가 맞더라도 현재 페이지 목적에 제시된 처방이 맞지 않으면 왜 적용하면 안 되는지와 실무적인 절충안을 설명해 주세요. 확인된 명시적 Google 정책 위반은 현상 유지를 안전한 답으로 제시하지 말고 정책을 지키는 대안을 제안해 주세요. 적절한 수정만 적용하고 데스크톱·모바일에서 테스트한 뒤 변경 파일·검증 결과·미적용 사유를 알려 주세요. 배포와 계정 설정은 제 승인 없이 진행하지 마세요.

페이지 내용이 검사 이후 바뀌었거나 PDF에 적힌 현상을 재현하지 못하면 코딩 AI가 임의로 해당 부분을 수정하지 않고 소유자에게 확인해야 합니다. 권고를 미적용하더라도 과거 보고서의 관찰과 점수를 소급 변경하지 않고 결정 이유를 별도로 남깁니다.

## 보고서 전달 시 복사 문구

아래 대괄호 항목을 실제 보고서 숫자나 `평가 불가` 표시로 바꿔 보냅니다. 관리 화면의 복사 버튼을 쓰면 URL·방문 수·점수·추정 지수·검증률·점수 구간이 채워진 문구를 복사할 수 있습니다. ChatGPT v11에서 만든 PDF에는 [프로젝트 운영법](./ChatGPT-프로젝트-운영법-v11.md)의 전달문을 사용할 수 있습니다.

> 요청하신 [사이트 URL] 검수를 마쳐 PDF를 보내드립니다. 발견한 공개 URL [발견 수]개 중 [실제 검사 수]개를 직접 확인했고, 이번 검사 범위의 통합 자체 점수는 **[점수]/100점**입니다. 같은 숫자의 비공식 AdSense 승인 가능성 추정 지수는 **[점수]%**이며 실제 승인 확률은 아닙니다. 첫 장의 100점 채점 기준표와 검증률·미확인 항목을 함께 확인해 주세요. 본문에는 크리티컬·긴급·수정 필요 항목의 페이지별 관찰 근거와 수정 방법을 적었습니다. PDF의 예시 코드는 현재 저장소에서 다시 확인해 적용·대안 적용·보류·유지 여부를 판단해 주세요.

빠른 검사의 관리 화면 복사 버튼은 마지막 문장을 다음과 같이 바꿉니다: **이번 보고서는 빠른 표본 검사(최대 20페이지) 결과이며, 사이트 전체 페이지를 검사했다는 뜻은 아닙니다.**

## 파일과 접근 권한

고객에게는 PDF만 보냅니다. 소스코드·검사 규칙·관리자 문구와 HTML·JSON 재검토 자료는 관리자 컴퓨터에 보관합니다. 검사 작업은 `~/Library/Application Support/AdSense Auditor/`의 파일에 저장됩니다. 로그인 화면은 없으므로 Mac 사용자 계정 권한과 FileVault로 파일과 실행 중인 화면을 보호하세요.
